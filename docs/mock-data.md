# 연습용 문의 14건

`supabase/seed.sql`이 채워 넣는 데이터입니다. 화면을 만들면서 마주칠 경우를 빠짐없이
덮도록 골랐습니다. 이름·회사명·연락처는 전부 가상이고 이메일은 `example.com`입니다.

## 덮는 경우

| 항목 | 내용 |
|---|---|
| 유형 5단계 | 안정형 4 · 안정추구형 3 · 위험중립형 2 · 적극투자형 3 · 공격투자형 2 |
| 상태 5단계 | 신규 3 · 검토중 3 · 결과지 발송 2 · 상담 진행 2 · 종료 4 |
| 종료 사유 | 계약 · 금액 미달 · 연락 불가 · 고객 보류 |
| 금액 미달 | `INQ-2026-0131`, `INQ-2026-0146` — 안내 문구 노출 확인용 |
| 모름 응답 많은 건 | `INQ-2026-0141` 윤소미, 4건 |
| 발송 기한 초과 | `INQ-2026-0140`, `INQ-2026-0141`, `INQ-2026-0145` — 목록 맨 위로 올라옴 |
| 조건부 문항 | 채워진 건(`0136`, `0140`, `0144`)과 숨겨진 건 둘 다 |
| 담당자 미배정 | `INQ-2026-0141`과 신규 3건 |
| 자유 입력 빈 건 | `0131`, `0141`, `0143`, `0144`, `0146`, `0147` |

접수 시각은 `seed.sql`을 실행한 시점 기준 상대 시각으로 들어갑니다. 즉 언제 넣든
목록이 "1일 전 / 3시간 전"처럼 최근 문의로 보입니다.

## 진단 결과는 손으로 적지 않았습니다

문의에는 답변만 들어 있고, 유형·점수는 `src/lib/domain/scoring.ts`가 계산한 값을
시드 생성 시점에 굳혀 넣습니다. 배점을 고쳤을 때 데이터가 조용히 어긋나는 것을 막기
위해서입니다.

`src/lib/mock/fixtures.ts`의 각 건에는 `expectedTier`가 붙어 있고, 시드를 다시 뽑을 때
계산 결과와 다르면 **생성이 실패합니다.** 지금은 14건 전부 일치합니다.

```bash
npm run seed:gen
```

## 진단이 굳어 있는 이유

`inquiries.diagnosis` 컬럼에는 **접수 시점의 판정**이 통째로 들어 있습니다. 나중에
배점(`choices.score`)을 바꿔도 과거 문의의 진단이 소급해서 달라지지 않습니다.

고객에게 이미 "위험중립형입니다"라고 안내한 건이 어느 날 조용히 "안정형"으로 바뀌면
안 되기 때문입니다.

## 데이터를 처음부터 다시 채우고 싶을 때

`supabase/schema.sql`을 다시 실행하면 표가 모두 지워지고 새로 만들어집니다.
그다음 `seed.sql`을 실행하면 됩니다. 연습 중에 넣은 문의는 함께 사라집니다.
